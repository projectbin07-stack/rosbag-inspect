# Contributing

Bug reports, bags that are read or judged wrongly, and pull requests are welcome.

## Development setup

```console
git clone https://github.com/projectbin07-stack/rosbag-inspect.git
cd rosbag-inspect
python -m venv .venv
.venv/bin/pip install -e ".[dev]"      # Windows: .venv\Scripts\pip
```

## Checks

All four must pass; CI runs them on Ubuntu and Windows with Python 3.10, 3.13 and 3.14.

```console
ruff check .
ruff format --check .
mypy
pytest --cov
```

## Guidelines

- Keep the runtime free of third-party dependencies, and in particular of compiled extensions.
- Format readers follow the public specifications listed in `docs/formats.md`. Do not copy code
  from other bag readers; cite the specification section you implemented instead.
- New checks need a test whose expected value is derived by hand, with the derivation in a
  comment or docstring. Do not assert against numbers copied from the tool's own output.
- Fixtures are generated by `tests/bagwriter.py` and `tests/drive.py`. Do not commit bag files.
  If a real bag triggers a bug, reduce it to the few messages that matter and rebuild them with
  the writer in a test.
- Do not state performance or compatibility claims in documentation unless you measured or
  tested them and say how.
- Keep commits small with imperative messages (`Add ...`, `Fix ...`).

## Reporting a wrong result

Include the command, the `--json` output, what you expected, the ROS 2 distribution and storage
plugin that recorded the bag, and if possible `rosbag-inspect info --json` and a small excerpt
(`rosbag-inspect echo BAG TOPIC --limit 3`) of the topic involved. Please do not attach bags you
are not allowed to share.
